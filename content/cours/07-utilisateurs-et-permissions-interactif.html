Linux initiation · Chapitre 07

Qui peut faire quoi ?

Choisissez une identité. Décodez les droits.
Changez les permissions et observez leurs effets.

Un fichier · trois catégories

-rw-r-----
alice   stagiaires   notes.txt

D’abord : qui agit ?

Un compte, une identité, des groupes.

Les exemples ci-dessous sont simulés. Aucune modification n’est faite sur votre machine.

Interroger son identité

Choisissez une personne, puis une commande.

alice@debian:~$ whoami

alice

whoami affiche le nom de l’utilisateur qui exécute la commande.

Les trois questions à se poser

  1. 1Quel utilisateur agit ?Son nom et son identifiant numérique, l’UID.
  2. 2À quels groupes appartient-il ?Un même compte peut appartenir à plusieurs groupes.
  3. 3À qui appartient le fichier ?Chaque fichier a un propriétaire et un groupe associé.
sudo change les privilèges de la commande. Il ne change pas le propriétaire de tous vos fichiers. Dans cet exemple Debian, Alice est autorisée à utiliser sudo ; Bob et Camille ne le sont pas.
Repères pour gérer les comptes

sudo adduser aliceCréer un compte interactivement sur Debian.

passwdChanger son mot de passe ; sudo passwd alice cible le compte Alice.

sudo usermod -aG stagiaires bobAjouter Bob sans retirer ses autres groupes. Une nouvelle session est généralement nécessaire.

sudo deluser bobSupprimer le compte. L’option --remove-home supprime aussi son dossier personnel : vérifiez avant de l’utiliser.

root est un compte particulier (UID 0). On garde un compte normal pour le quotidien et on utilise les privilèges administrateur lorsque c’est nécessaire. Le laboratoire de droits utilise des comptes ordinaires.

Ensuite : qui possède la ressource ?

Dépliez une ligne de ls -l.

Cliquez sur les blocs : les lettres ont une place et une fonction précises.

alice@debian:~$ ls -l notes.txt

11234   13 oct   notes.txt

u — Le propriétaire

Alice possède ce fichier. Le bloc rw- lui permet de lire et modifier son contenu, pas de l’exécuter.

rLire

Lire le contenu du fichier.

wModifier

Modifier le contenu du fichier.

xExécuter

Autoriser son lancement comme programme, si le fichier s’y prête.

Un seul bloc s’applique : propriétaire d’abord ; sinon groupe si l’utilisateur en est membre ; sinon autres. On n’additionne pas les droits de ces trois blocs.

Enfin : quels droits donner ?

Manipulez. Observez. Comprenez.

Les droits et les commandes évoluent ensemble. Toutes les modifications sont simulées.

chmod modifie les droits, pas le propriétaire ou le groupe. La commande doit être exécutée par le propriétaire ou avec les privilèges appropriés.

A

Alice essaie d’accéder au fichier

Groupes : stagiaires, sudo
Bloc utilisé : propriétaire (u)

Alice est le propriétaire : seuls les droits du bloc u s’appliquent.

Pour supprimer un fichier, ce sont surtout les droits sur son dossier parent qui comptent.

Ce que suppose le laboratoire

Nous étudions les droits classiques rwx, pour des comptes ordinaires. Les dossiers parents sont traversables. Les ACL, les droits spéciaux, les montages et les restrictions supplémentaires ne sont pas simulés. Un droit x ne transforme pas un document en programme.

Ajouter ou retirer un droit

Le mode symbolique permet de toucher uniquement aux droits choisis.

Essayez u+x : l’exécution s’ajoute au propriétaire, sans changer les autres blocs.

Changer qui possède la ressource

Changez l’association, puis observez quel bloc s’applique à Alice, Bob ou Camille.

sudo chown alice:stagiaires notes.txt

chown change le propriétaire et/ou le groupe. Les bits rwx restent les mêmes.

Passez d’une intention à des droits

Trois missions, le minimum nécessaire.

Chaque mission prépare l’atelier. Vous choisissez les cases à cocher.

01

Un document privé

Alice doit pouvoir lire et modifier ses notes. Ni le groupe, ni les autres ne doivent y accéder. Aucun droit d’exécution n’est nécessaire.

02

Partager un document

Alice lit et modifie le document. Les stagiaires peuvent seulement le lire. Les autres n’ont aucun droit. Personne ne l’exécute.

03

Un dossier d’équipe

Alice peut lister, traverser et créer dans le dossier. Les stagiaires peuvent lister et traverser, sans créer ni supprimer. Les autres n’y accèdent pas.

Un refus d’accès ne se résout pas systématiquement avec 777. Identifiez l’utilisateur, le bon bloc et le droit manquant avant de modifier les permissions.
