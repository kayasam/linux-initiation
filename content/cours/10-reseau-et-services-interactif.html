Réseau — interfaces et connectivité

Afficher les interfaces réseau

ip address          # toutes les interfaces et leurs IPs
ip -br address     # version courte et lisible (brief)

Tester la connectivité avec ping

ping 8.8.8.8           # teste vers Google DNS (Ctrl+C pour arrêter)
ping google.com        # teste aussi la résolution DNS
ping -c 4 google.com   # envoie exactement 4 paquets puis s'arrête
Astuce Si ping 8.8.8.8 fonctionne mais ping google.com échoue, le problème vient de la résolution DNS (pas du réseau lui-même).

Ports en écoute et routage

ss -tulnp            # liste les ports en écoute (TCP/UDP)
ss -tulnp | grep 22  # vérifier si SSH écoute sur le port 22
ip route              # affiche la table de routage

SSH — connexion distante sécurisée

SSH (Secure Shell) permet de se connecter à un serveur distant en ligne de commande, de façon chiffrée. C'est l'outil fondamental de l'administration Linux.

Analogie SSH, c'est comme un téléphone sécurisé entre vous et le serveur. Tout ce que vous tapez et tout ce que le serveur répond est chiffré. Personne sur le réseau ne peut lire la conversation.

Se connecter en SSH

ssh utilisateur@adresse_ip
ssh stagiaire@192.168.1.10
ssh -p 2222 stagiaire@192.168.1.10   # port non standard

Quitter une session SSH

exit       # quitter la session SSH (ou Ctrl+D)
Conseil professionnel SSH est l'outil principal de l'administration Linux professionnelle. Dans un datacenter, on ne branche jamais un clavier sur un serveur — on se connecte toujours en SSH depuis sa machine.

Copier des fichiers via SSH

# Copier un fichier LOCAL vers un serveur DISTANT
scp fichier.txt stagiaire@192.168.1.10:/home/stagiaire/

# Copier un fichier DISTANT vers LOCAL
scp stagiaire@192.168.1.10:/etc/hosts ./hosts-distant.txt

DNS — résolution des noms de domaine

Le DNS (Domain Name System) traduit les noms lisibles par les humains (google.com) en adresses IP (142.250.74.46) que les machines comprennent.

Analogie Le DNS est l'annuaire téléphonique d'Internet : vous cherchez "Google" et il vous donne le numéro (l'adresse IP) à appeler.

Tester la résolution DNS

host google.com          # résolution simple
nslookup google.com      # résolution avec infos du serveur DNS

Configuration DNS du système

cat /etc/resolv.conf     # serveurs DNS configurés

/etc/hosts — résolution locale sans DNS

Le fichier /etc/hosts permet de définir des correspondances nom ↔ IP locales, sans passer par un serveur DNS externe. Ce fichier est consulté en priorité avant le DNS.

cat /etc/hosts

# Contenu typique :
127.0.0.1       localhost
127.0.1.1       hostname-de-la-machine
192.168.1.10    mon-serveur     # entrée personnalisée
Cas pratique En lab, on peut ajouter une ligne dans /etc/hosts pour accéder à un VM par son nom plutôt que par son IP : 192.168.56.101 debian-lab. On peut ensuite faire ssh stagiaire@debian-lab.

Ordre de résolution des noms

PrioritéSourceFichier/Service
1 (prioritaire)Fichier local/etc/hosts

3 (fallback)Autres méthodesmDNS, NIS... (cas rares)

Services — systemctl

Un service (ou daemon) est un programme qui tourne en arrière-plan en permanence : SSH, serveur web, base de données, etc. On les gère avec systemctl.

Machine à états d'un service — cliquez sur une action

État : inconnu
Cliquez sur une action pour voir la commande et son effet.

Toutes les commandes systemctl

sudo systemctl status ssh       # état du service ssh
sudo systemctl start ssh        # démarrer
sudo systemctl stop ssh         # arrêter
sudo systemctl restart ssh      # redémarrer (stop + start)
sudo systemctl reload ssh       # recharger la config sans couper
sudo systemctl enable ssh       # démarrer automatiquement au boot
sudo systemctl disable ssh      # ne plus démarrer au boot
systemctl list-units --type=service  # lister tous les services

Consulter les logs avec journalctl

sudo journalctl -u ssh                        # tous les logs du service ssh
sudo journalctl -u ssh -f                     # logs en temps réel (Ctrl+C pour quitter)
sudo journalctl -u ssh --since "1 hour ago"  # logs de la dernière heure
Différence enable / start start = démarre maintenant (actif jusqu'au prochain reboot).
enable = démarre automatiquement à chaque boot (mais ne démarre pas immédiatement).
Pour les deux en une fois : sudo systemctl enable --now ssh
