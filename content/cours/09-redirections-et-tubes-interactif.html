Linux Initiation

09 — Redirections et tubes

Flux, >, >>, pipes — connecter et rediriger les entrées/sorties des commandes

Les 3 flux d'une commande

Chaque commande Linux communique avec l'extérieur via 3 canaux :

clavier stdin (0)
→
[commande] traitement
→
écran stdout (1) — résultats
↑
écran stderr (2) — erreurs
Analogie — machine à café Les grains de café = stdin (ce qu'on fournit). Le café dans la tasse = stdout (le résultat). Le voyant d'erreur qui clignote = stderr (le message d'erreur si ça plante).

Tableau des flux

FluxNuméroDéfautDescription
stdin0ClavierEntrée standard — données fournies à la commande
stdout1ÉcranSortie standard — résultat normal de la commande
stderr2ÉcranSortie d'erreur — messages d'erreur séparés du résultat

L'intérêt : stdout et stderr sont séparés, ce qui permet de rediriger les erreurs indépendamment des résultats.

Redirections — vers les fichiers

Les 3 opérateurs — cliquez pour détailler

Cliquez sur un opérateur pour voir son fonctionnement.

Rediriger stdout avec >

Attention > écrase le fichier existant sans avertissement ! Si le fichier contient des données importantes, elles seront perdues. 
ls /etc > liste.txt
date > date_du_jour.txt

Ajouter à la fin avec >>

echo "Ligne 1" > journal.txt
echo "Ligne 2" >> journal.txt   # ajoute sans écraser
echo "Ligne 3" >> journal.txt

Rediriger stderr avec 2>

ls /inexistant 2> erreurs.txt
ls /etc /inexistant &> tout.txt  # stdout ET stderr ensemble

/dev/null — le trou noir

/dev/null est un fichier spécial qui supprime tout ce qu'on lui envoie. Utile pour ignorer les erreurs.

ls /inexistant 2> /dev/null   # erreur supprimée
commande &> /dev/null           # tout supprimé (mode silencieux)

Tubes et pipes — enchaîner les commandes

Le symbole | (pipe, tube) connecte la sortie (stdout) d'une commande à l'entrée (stdin) de la suivante.

Analogie — plomberie Un robinet → un tuyau → un seau. L'eau (les données) coule de gauche à droite sans toucher le disque. Chaque commande filtre ou transforme les données avant de les passer à la suivante.

Exemples progressifs

ls /etc | wc -l → compte le nombre de fichiers dans /etc
ps aux | grep firefox → cherche le processus firefox
apt list --installed | head -5 → affiche les 5 premiers paquets
cat /etc/passwd | grep stagiaire → filtre la ligne du stagiaire
ls /etc | sort | uniq | wc -l → 4 commandes enchaînées

grep — filtrer par motif

grep affiche uniquement les lignes d'un fichier (ou d'un pipe) qui contiennent un motif donné. C'est l'un des outils les plus utilisés en ligne de commande.

Options grep — cliquez pour détailler

Usage de base

grep "motif" fichier
Affiche toutes les lignes du fichier contenant "motif". Les guillemets sont recommandés si le motif contient des espaces.

-i (insensible à la casse)

grep -i "error" fichier
Trouve "error", "Error", "ERROR", "eRrOr"... Très utile pour les fichiers de logs.

-n (numéros de ligne)

grep -n "motif" fichier
Affiche le numéro de chaque ligne trouvée. Pratique pour aller directement modifier la ligne dans un éditeur.

-v (inverse)

grep -v "motif" fichier
Affiche les lignes qui NE contiennent PAS le motif. Utile pour exclure certains résultats.

-r (récursif)

grep -r "mot" /etc/
Cherche dans tous les fichiers d'un dossier et ses sous-dossiers. Peut générer beaucoup de résultats sur /etc/.

-c (compter)

grep -c "motif" fichier
Affiche uniquement le nombre de lignes correspondantes, pas leur contenu.

Exemples combinés avec pipes

cat /var/log/syslog | grep -i "error"
grep -i "error" /var/log/syslog | wc -l
cat /etc/passwd | grep "/bin/bash"
cut -d: -f1 /etc/passwd | sort
