Le shell et son environnement

Chapitre 01 — shell, flux, variables, alias, fonctions

# Le shell

Sous Unix/Linux, le shell est l'interpréteur de commandes qui fait office d'interface entre l'utilisateur et le système d'exploitation. Il possède un double rôle : environnement interactif de travail (on tape des commandes) et langage de programmation (on écrit des scripts).
Note — Étymologie
Le mot shell signifie "coquille" en anglais. C'est la coquille qui entoure le noyau (kernel) du système. Tu interagis avec la coquille, pas directement avec le noyau.

Le prompt

Quand tu ouvres un terminal, le shell affiche un prompt — le signe qui indique qu'il est prêt.

samuel@debian:~$ ← utilisateur normal root@debian:~# ← superutilisateur (root)

Format général : utilisateur@machine:répertoire$

Le $ devient # pour root — rappel visuel qu'on a les pleins pouvoirs.

Les différents shells

ShellNom completNotes
sh Bourne Shell Shell historique (1977), standard POSIX — base de compatibilité
bash Bourne Again Shell Standard sur la plupart des Linux — utilisé dans ce cours
zsh Z Shell Shell par défaut de macOS et Kali Linux, plus puissant en interactif
dash Debian Almquist Shell Très rapide, utilisé par Debian/Ubuntu pour les scripts système
fish Friendly Interactive Shell Moderne, pensé pour la facilité d'utilisation
Dans ce cours
On travaille avec bash. C'est le shell le plus répandu sur Linux — celui que tu trouveras sur presque tous les serveurs.
Note
Sur la plupart des systèmes modernes, sh est un lien symbolique vers bash ou dash — le Bourne Shell d'origine n'est plus utilisé.

Identifier son shell

echo $SHELL # shell configuré pour ton utilisateur echo $0 # shell du processus courant (-bash = login shell) cat /etc/shells # liste les shells disponibles sur le système

Types de shell

Bash distingue deux axes indépendants :

Login shell vs Non-login

TypeExemple
LoginConnexion SSH, TTY console
Non-loginNouveau terminal en session graphique
shopt login_shell # on ← login shell # off ← non-login shell

Interactif vs Non-interactif

Interactif : tu tapes des commandes, il répond. Terminal ouvert à la main.

Non-interactif : aucune intervention humaine. Script ou tâche cron.

Pourquoi c'est important
Bash ne charge pas les mêmes fichiers de configuration selon le type de shell. C'est ce qu'on détaille dans l'onglet Environnement.

# Environnement

Variables d'environnement

L'environnement d'un shell est un ensemble de variables transmises aux processus qu'il lance. Elles permettent de paramétrer le comportement du système et des programmes.

Variable locale

Visible uniquement dans le shell courant. Non transmise aux processus enfants.

MON_VAR="bonjour" echo $MON_VAR

Variable exportée

Transmise aux processus enfants (scripts, commandes lancées).

export MON_VAR="bonjour" export MON_VAR # exporte une var déjà définie
env # affiche tout l'environnement printenv PATH # affiche une variable précise echo $HOME # même chose, syntaxe shell

Variables clés

VariableContenuExemple
$PATH Dossiers où bash cherche les commandes /usr/bin:/usr/local/bin:…
$HOME Répertoire personnel de l'utilisateur /home/samuel
$USER Nom de l'utilisateur courant samuel
$PS1 Format du prompt \u@\h:\w\$
$SHELL Shell configuré pour l'utilisateur /bin/bash
$PWD Répertoire courant /etc/nginx
Attention — PATH
Si bash répond "command not found" pour un programme que tu viens d'installer, c'est souvent que son dossier n'est pas dans $PATH. Vérifie avec echo $PATH et ajoute si besoin dans ~/.bashrc : export PATH="$PATH:/nouveau/dossier"

Shell non-login (terminal graphique)
Un terminal ouvert dans une session graphique charge directement : /etc/bash.bashrc (global) puis ~/.bashrc (personnel). Les scripts non-interactifs ne chargent aucun fichier de config par défaut.
En pratique
Tu mets presque tout dans ~/.bashrc : alias, fonctions, variables personnalisées. C'est le fichier chargé à chaque fois que tu ouvres un terminal.

/etc/skel — modèle des nouveaux utilisateurs

Quand un compte est créé (useradd / adduser), les fichiers de /etc/skel sont copiés dans son répertoire personnel.

ls -la /etc/skel # .bash_logout .bashrc .profile

Si tu veux que tous les nouveaux utilisateurs aient un .bashrc personnalisé, modifie /etc/skel/.bashrc.

Recharger la configuration sans redémarrer

source ~/.bashrc # ou version courte (POSIX) : . ~/.bashrc
Attention
Exécuter bash ~/.bashrc lance un sous-shell — les changements ne s'appliquent PAS au shell courant. Il faut absolument utiliser source ou ..

# Flux & Tubes

Les trois flux standard

Chaque commande Linux dispose de trois flux de données :

stdin (0) ──────► commande ──────► stdout (1)
└──────► stderr (2)
FluxNuméroDéfautDescription
stdin0Clavier Entrée standard — données reçues par la commande
stdout1Écran Sortie standard — résultat normal
stderr2Écran Sortie d'erreur — messages d'erreur
Attention
stdout et stderr sont tous les deux affichés à l'écran par défaut — mais ce sont deux flux séparés. Cela a son importance quand on redirige.

Les redirections

OpérateurEffet
>Redirige stdout vers un fichier (écrase s'il existe)
>>Redirige stdout et ajoute à la fin du fichier
2>Redirige stderr vers un fichier (écrase)
2>>Redirige stderr et ajoute à la fin du fichier
&>Redirige stdout ET stderr vers un fichier
2>&1Redirige stderr vers stdout
<Utilise un fichier comme entrée stdin
# stdout vers fichier (écrase) ls /etc > liste.txt # stdout vers fichier (ajoute) ls /var >> liste.txt # stderr vers fichier ls /inexistant 2> erreurs.txt # stdout ET stderr ensemble ls /etc /inexistant &> tout.txt # ou version longue équivalente : ls /etc /inexistant > tout.txt 2>&1 # ignorer stderr (jeter les erreurs) ls /inexistant 2> /dev/null # stdin depuis un fichier wc -l < /etc/passwd
Note — /dev/null
/dev/null est le "trou noir" : tout ce qu'on y envoie est jeté. Très utile pour ignorer les erreurs qu'on ne veut pas voir.

Les tubes (pipes)

Le tube | (pipe) connecte la sortie stdout d'une commande à l'entrée stdin de la suivante.

# Compter le nombre de fichiers dans /etc ls /etc | wc -l # Filtrer les lignes contenant "error" dans un log cat /var/log/syslog | grep "error" # Enchaîner plusieurs tubes cat /etc/passwd | grep bash | cut -d: -f1 | sort
Philosophie Unix
Le tube est l'une des idées les plus puissantes d'Unix : des petites commandes spécialisées, combinées ensemble, font des traitements complexes.

# Alias & Fonctions

Les alias

Un alias est un raccourci : un mot court qui remplace une commande plus longue.

# Syntaxe alias nom='commande'

Exemples courants — cliquez sur une carte pour voir les détails :

alias ll='ls -lh' nav ▶

Affiche le contenu d'un dossier en format long avec des tailles lisibles (-h = human-readable : Ko, Mo, Go).

ls -lha ajoute les fichiers cachés (ceux qui commencent par .).

alias ..='cd ..' nav ▶

Remonte d'un niveau dans l'arborescence. alias ...='cd ../..' remonte de deux niveaux.

alias rm='rm -i' sécurité ▶

Le flag -i (interactive) demande une confirmation avant chaque suppression. Même chose pour cp -i et mv -i.

Pour contourner ponctuellement l'alias : \rm fichier.txt

alias cp='cp -i' sécurité ▶

Demande confirmation avant d'écraser un fichier existant. Évite les pertes de données par inadvertance.

alias ports='ss -tulnp' réseau ▶

Affiche tous les ports en écoute sur le système. Les flags : -t TCP, -u UDP, -l listening, -n numérique, -p processus.

alias myip='ip -br a' réseau ▶

Affiche les interfaces réseau et leurs adresses IP dans un format compact et lisible.

alias sctl='sudo systemctl' système ▶

Raccourci pour systemctl avec sudo. Usage : sctl status nginx, sctl restart ssh.

alias maj='sudo apt update && sudo apt full-upgrade' système ▶

Met à jour les listes de paquets puis installe toutes les mises à jour disponibles en une seule commande.

Gérer les alias

# Temporaire (valable seulement dans ce terminal) alias bonjour='echo "Bonjour !"' # Permanent → l'ajouter dans ~/.bashrc, puis recharger source ~/.bashrc # Lister tous les alias actifs alias # Supprimer un alias temporairement unalias bonjour # Contourner un alias ponctuellement (appelle l'exécutable réel) \rm fichier.txt
Attention
Les alias ne sont présents que sur ta machine. Ne compte pas sur eux quand tu travailles sur un serveur inconnu. Sur un serveur de prod, rm n'a pas le -i — fais attention.

Les fonctions shell

Un alias ne peut faire qu'une chose simple. Pour des comportements plus complexes (arguments, conditions, plusieurs commandes), on utilise une fonction.

# Syntaxe recommandée nom_fonction() { commandes } # Exemples : # Créer un dossier et s'y déplacer directement mkcd() { mkdir -p "$1" && cd "$1" } # Afficher l'utilisation disque triée du_top() { du -sh "$1"/* 2>/dev/null | sort -rh | head -10 } # Utiliser la fonction avec un argument mkcd mon-projet # crée le dossier et va dedans du_top /var # affiche les 10 plus gros éléments de /var
Arguments
Les arguments se récupèrent avec $1, $2… comme dans un script. $@ représente tous les arguments d'un coup.

Alias vs Fonction — quand utiliser quoi ?

SituationUtiliser
Renommer une commande, ajouter des options par défautAlias
Utiliser des arguments ($1, $2…)Fonction
Plusieurs commandes enchaînées avec logiqueFonction
Traitement conditionnel (if, for…)Fonction
Astuce
Les fonctions définies dans ~/.bashrc sont disponibles dans tous tes terminaux, comme les alias.

# Quiz de révision

Testez vos connaissances — cliquez sur la bonne réponse.

1. Quelle commande affiche le shell configuré pour l'utilisateur courant ?
$SHELL contient le chemin du shell configuré pour l'utilisateur dans /etc/passwd. $0 affiche le shell du processus courant (valeur différente en login shell : -bash avec le tiret).
2. Tu modifies ~/.bashrc. Quelle commande applique les changements dans le terminal ouvert sans le fermer ?
source ~/.bashrc (ou . ~/.bashrc) exécute le fichier dans le shell courant — les changements s'appliquent immédiatement. bash ~/.bashrc lance un sous-shell : les changements ne remontent pas au shell parent.
3. Tu exécutes : ls /etc > liste.txt puis ls /tmp > liste.txt. Que contient liste.txt ?
> écrase le fichier à chaque fois. Le deuxième ls /tmp > liste.txt remplace le contenu. Pour ajouter, il faut utiliser >>.
4. Tu veux exécuter rm sans le -i de ton alias rm='rm -i'. Comment faire ?
Précéder d'un antislash \rm désactive l'interprétation de l'alias et appelle directement l'exécutable système. command rm fonctionne aussi, mais \ est plus rapide à taper.
5. Quelle variable d'environnement liste les dossiers où bash cherche les commandes ?
$PATH est une liste de chemins séparés par : que bash parcourt dans l'ordre pour trouver une commande. Si un programme n'est pas dans $PATH, bash répond "command not found".
6. Un alias peut-il recevoir des arguments comme $1, $2 ?
Un alias est une simple substitution de texte : il ne peut pas traiter des arguments. Pour recevoir $1, $2… ou faire de la logique, il faut écrire une fonction shell.
7. Quel fichier de configuration est chargé lors d'une connexion SSH sur Debian ?
Une connexion SSH ouvre un login shell : bash charge d'abord /etc/profile puis ~/.bash_profile. Ce dernier source souvent ~/.bashrc, ce qui fait que les alias sont disponibles. Un terminal graphique (non-login) charge directement ~/.bashrc.
