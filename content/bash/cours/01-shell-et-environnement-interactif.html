Même commande, deux interpréteurs
Est-ce que tout se comprend pareil ?
Dans Bash et dans le sh de notre Debian, prédis le résultat de ces commandes. Aucun fichier n’est créé.
bash -c 'echo fichier{1..3}.txt'
sh -c 'echo fichier{1..3}.txt'
Bash : fichier1.txt fichier2.txt fichier3.txt
sh → dash : fichier{1..3}.txt
Les accolades sont une extension comprise par Bash, pas par dash.
Sur ta VM Debian
Qui travaille vraiment ?
Ces commandes donnent trois informations différentes. Tape seulement les commandes, sans ajouter l’invite $.
cat /etc/shells
readlink -f /bin/sh
ps -p $$ -o comm=
  • /etc/shells : les shells de connexion déclarés.
  • readlink -f : ici, /usr/bin/dash.
  • ps : ici, le shell courant est bash.
Attention : $SHELL renseigne normalement le shell de connexion configuré. Il ne change pas automatiquement quand tu en lances un autre.


La fenêtre n’est pas l’interpréteur. Regarde comment ta commande voyage jusqu’à Bash.

Interactif, non interactif, de connexion…
Interactif : Bash attend ce que tu tapes, comme après SSH.
Non interactif : Bash reçoit un script ou une commande avec -c.
De connexion : le shell initialise l’environnement d’une nouvelle session. C’est une autre distinction.
Les fichiers lus peuvent varier selon le mode. ~/.bashrc sert notamment aux réglages des Bash interactifs.

Une cabine, sa propre copie
Le sous-shell part. Le parent reste.
Un shell peut en lancer un autre. Les parenthèses créent un sous-shell avec une copie de son environnement.

Le bon repère : cd change le dossier du shell qui l’exécute. Le changement effectué dans le sous-shell ne remonte pas au parent. Un cd /tmp directement dans le parent change bien son dossier.


Et si je lance bash ?
Taper bash démarre un nouveau Bash enfant. exit termine cet enfant et te ramène au parent. Un nouvel exit dans le parent ferme ensuite la connexion SSH.
bash -c 'echo "Bonjour depuis le Bash enfant"'
echo "De retour dans le shell parent"
-c donne la commande au Bash enfant, qui se termine après l’avoir exécutée. La transmission des variables avec export arrive au chapitre 02.
Le piège du disque partagé
Un fichier créé dans un sous-shell reste-t-il présent après sa fin ?
On reste sur la même VM. Les sous-shells ne sont ni une nouvelle connexion SSH, ni une copie du disque.


À tester sur Debian : remplace /tmp par /etc dans le groupe. Seul le résultat du milieu doit changer.

Ton espace de travail sur Debian
Ce bloc crée un dossier réservé à la formation. -p crée aussi les parents manquants et accepte un dossier existant.
mkdir -p ~/atelier-bash/decouverte
cd ~/atelier-bash/decouverte
pwd
Avant d’écrire avec > : vérifie ton dossier avec pwd et le nom du fichier. L’ancien contenu de la destination sera remplacé.
Quatre raccourcis pour respirer
Clique sur un raccourci pour découvrir son effet dans le terminal.
De l’aide : ls --help, help cd et man ls (quitter avec q).


Bonus : un alias temporaire
alias ll='ls -l'
ll
unalias ll
Un alias donne un raccourci à une commande dans le shell courant. Nous ne modifions pas encore ~/.bashrc.
