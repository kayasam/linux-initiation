Chapitre 04 — tests, opérateurs, if/elif/else, case

# Les tests

Un test évalue une condition et retourne un code de retour. C'est ce code que if, while et && lisent pour décider quoi faire.

0 = VRAI — l'inverse des autres langages

0
VRAI — test réussi
1–255
FAUX — test échoué
Attention
En bash, 0 signifie VRAI et toute autre valeur signifie FAUX. C'est l'inverse de la plupart des langages de programmation (Python, C, JS…). La logique vient des codes de retour Unix : 0 = succès, autre = erreur.

Les trois syntaxes — cliquez pour comparer

test -d /etc echo $? # 0 ← vrai test -f /etc echo $? # 1 ← faux, /etc est un dossier, pas un fichier

Syntaxe longue, la commande test de base. Rarement utilisée directement — préférer les crochets.

# Syntaxe POSIX — compatible tous les shells [ -d /etc ] ; echo $? # 0 ← vrai [ -f /etc ] ; echo $? # 1 ← faux # Opérateurs logiques POSIX dans [ ] [ -d /etc -a -r /etc ] # -a = ET [ -f /etc -o -d /etc ] # -o = OU

Équivalent à test. Compatible POSIX (sh). Espaces obligatoires autour des crochets. À utiliser pour les scripts portables.

# Syntaxe bash étendue — RECOMMANDÉE [[ -d /etc ]] ; echo $? # 0 ← vrai [[ -f /etc ]] ; echo $? # 1 ← faux # Opérateurs logiques natifs dans [[ ]] [[ -d /etc && -r /etc ]] # ET [[ -f /a || -d /a ]] # OU [[ ! -e /tmp/lock ]] # NON # Supporte les motifs glob et regex [[ "$fichier" == *.sh ]] # glob [[ "$chaine" =~ ^[0-9]+$ ]] # regex POSIX étendue

Syntaxe recommandée dans tout script bash. Plus sûre (pas besoin de guillemets obligatoires), supporte &&, ||, !, les globs et les expressions régulières.

Règle simple
[[ ]] dans les scripts bash. [ ] uniquement si le script doit tourner avec sh (POSIX strict).

Opérateurs logiques combinés

# ET — les deux conditions doivent être vraies [[ -d "$rep" && -w "$rep" ]] && echo "dossier accessible en écriture" # OU — au moins une condition doit être vraie [[ -f "$f" || -L "$f" ]] && echo "fichier ou lien symbolique" # NON — inverse le résultat [[ ! -e "$fichier" ]] && echo "le fichier n'existe pas"
Note — && et || hors des crochets
&& et || s'utilisent aussi entre commandes, sans crochets : mkdir /tmp/test && echo "créé" — le echo ne s'exécute que si mkdir réussit.

# Opérateurs de test

Cliquez sur un opérateur pour voir les détails et un exemple.

chaîne
-z "$var"
Vrai si la variable est vide
Le z vient de zero — longueur zéro.
a= [[ -z "$a" ]] ; echo $? # 0 ← vrai a=bonjour [[ -z "$a" ]] ; echo $? # 1 ← faux
chaîne
-n "$var"
Vrai si la variable est non vide
Le n vient de non-zero. L'inverse de -z. Utile pour vérifier qu'un argument a bien été fourni.
a=bonjour [[ -n "$a" ]] ; echo $? # 0 ← vrai
chaîne
"$a" = "$b"
Vrai si les deux chaînes sont identiques
Dans [[ ]] on peut aussi utiliser ==. Dans [ ], utiliser = (un seul =).
[[ "$os" == "debian" ]] && echo "C'est Debian"
chaîne
"$a" != "$b"
Vrai si les deux chaînes sont différentes
[[ "$USER" != "root" ]] && echo "Pas root"
numérique
-eq
Égal (equal)
a=5 ; b=5 [[ "$a" -eq "$b" ]] ; echo $? # 0 ← vrai
Ne pas utiliser = pour comparer des nombres : [ "10" = "9" ] compare des chaînes (résultat faux), pas des valeurs.
numérique
-ne
Différent (not equal)
[[ $# -ne 1 ]] && echo "Mauvais nombre d'arguments"
numérique
-lt
Inférieur (less than)
a=10 ; b=20 [[ "$a" -lt "$b" ]] ; echo $? # 0 ← vrai
numérique
-gt
Supérieur (greater than)
a=30 [[ "$a" -gt 18 ]] && echo "Majeur"
numérique
-le
Inférieur ou égal (less or equal)
[[ "$note" -le 10 ]] && echo "Insuffisant"
numérique
-ge
Supérieur ou égal (greater or equal)
[[ "$score" -ge 80 ]] && echo "Mention bien"
fichier
-e fichier
Vrai si le fichier ou dossier existe
Test générique — ne distingue pas fichier et dossier.
[[ -e /etc/hosts ]] && echo "existe"
fichier
-f fichier
Vrai si c'est un fichier ordinaire
Exclut les dossiers, liens symboliques seuls, devices…
[[ -f /etc/hosts ]] ; echo $? # 0 ← fichier ordinaire [[ -f /etc ]] ; echo $? # 1 ← c'est un dossier
fichier
-d fichier
Vrai si c'est un dossier
[[ -d /etc ]] ; echo $? # 0 ← c'est bien un dossier
fichier
-r / -w / -x
Vrai si le fichier est lisible / modifiable / exécutable
Vérifie les droits de l'utilisateur courant sur le fichier.
[[ -x /bin/bash ]] ; echo $? # 0 [[ -w /etc/passwd ]] ; echo $? # 1 (sauf root)
fichier
-s fichier
Vrai si le fichier est non vide (taille > 0)
Utile pour vérifier qu'un fichier de log ou de résultat contient bien quelque chose.
[[ -s "$log" ]] && echo "Le log contient des données"
fichier
-L fichier
Vrai si c'est un lien symbolique
[[ -L /bin ]] ; echo $? # 0 sur Debian (bin → usr/bin)
Erreur classique — guillemets obligatoires
Toujours mettre les variables entre guillemets doubles dans les tests. Sans guillemets, si la variable est vide, bash génère une erreur de syntaxe.
a= [ $a = "test" ] # ERREUR : bash voit [ = "test" ] [ "$a" = "test" ] # CORRECT

# if / elif / else

La commande if exécute des commandes uniquement si une condition est vraie (code retour = 0).

Structure complète — cliquez sur chaque ligne

1
if [[ -d "$repertoire" ]] ; then
if … ; then — évalue la condition. Si le code retour est 0 (vrai), les commandes du bloc suivant s'exécutent. Le ; avant then peut être remplacé par un retour à la ligne.
2
echo "$repertoire existe"
Commandes exécutées si la condition est vraie. L'indentation (4 espaces) n'est pas obligatoire mais indispensable pour la lisibilité.
3
elif [[ -e "$repertoire" ]] ; then
elif — optionnel, répétable. Testé uniquement si le if précédent était faux. On peut enchaîner autant de elif que nécessaire.
4
echo "$repertoire existe mais ce n'est pas un dossier"
Commandes du bloc elif.
5
else
else — optionnel, une seule fois. Exécuté si aucune des conditions précédentes n'était vraie. Il n'a pas de condition propre.
6
echo "$repertoire n'existe pas"
Commandes du bloc else.
7
fi
fi — ferme obligatoirement le bloc if. C'est if écrit à l'envers. Oublier le fi est une erreur de syntaxe courante.
↑ Cliquez sur une ligne pour voir son rôle

Exemples pratiques

Tester un fichier :

#!/usr/bin/env bash set -euo pipefail cible="$1" if [[ -f "$cible" ]] ; then echo "fichier ordinaire" elif [[ -d "$cible" ]] ; then echo "dossier" else echo "n'existe pas" fi

Valider les arguments :

#!/usr/bin/env bash set -euo pipefail if [[ $# -ne 1 ]] ; then echo "Usage : $0 <nom>" >&2 exit 1 fi echo "Bonjour, $1 !"

Tester si une commande est disponible

La bonne façon de vérifier si un outil est installé :

if command -v curl > /dev/null ; then echo "curl est installé" else echo "curl n'est pas installé" exit 1 fi
Note — command -v vs which
Préférer command -v à which : c'est une commande interne bash, plus fiable et portable. which est un programme externe dont le comportement varie selon les systèmes.

Comparaison numérique — exemple

#!/usr/bin/env bash set -euo pipefail a="$1" b="$2" if [[ "$a" -gt "$b" ]] ; then echo "$a est supérieur à $b" elif [[ "$a" -lt "$b" ]] ; then echo "$a est inférieur à $b" else echo "$a est égal à $b" fi

# La structure case

case simplifie les conditions à choix multiples sur une même variable. Équivalent à une série de if/elif, mais bien plus lisible quand il y a plus de 3 cas.

Syntaxe annotée

case "$variable" in motif1) commandes ;; ← obligatoire — ferme le bloc motif2 | motif3) ← plusieurs motifs pour le même bloc commandes ;; *) ← cas par défaut (comme else) commandes ;; esac
ÉlémentRôle
;;Ferme chaque bloc — obligatoire
|Sépare les motifs alternatifs pour un même bloc
*Correspond à tout le reste — cas par défaut
?Joker : n'importe quel caractère unique
esacFerme le case (case à l'envers)

Exemple — distributions Linux

Avec case
case "$distro" in debian | ubuntu | mint) echo "format DEB" ;; centos | fedora | opensuse) echo "format RPM" ;; *) echo "inconnu" ;; esac
Équivalent avec if/elif
# Moins lisible avec 6 valeurs… if [[ "$distro" == "debian" || "$distro" == "ubuntu" || "$distro" == "mint" ]] ; then echo "format DEB" elif [[ "$distro" == "centos" || "$distro" == "fedora" || "$distro" == "opensuse" ]] ; then echo "format RPM" else echo "inconnu" fi

Exemple — menu interactif

#!/usr/bin/env bash set -euo pipefail echo "Que voulez-vous faire ?" echo " 1) Afficher la date" echo " 2) Afficher l'espace disque" echo " 3) Quitter" read -p "Votre choix : " choix case "$choix" in 1) date ;; 2) df -h / ;; 3) echo "Au revoir !" ; exit 0 ;; *) echo "Choix invalide : $choix" >&2 ; exit 1 ;; esac

Insensibilité à la casse — nocasematch

shopt -s nocasematch # active — oui/OUI/Oui seront tous reconnus case "$reponse" in oui | o | yes | y) echo "Confirmé" ;; non | n | no) echo "Annulé" ;; esac shopt -u nocasematch # désactive après usage
Quand utiliser case plutôt que if
Dès qu'on compare la même variable à plus de 2 ou 3 valeurs. Pour des tests sur des types différents ou des conditions complexes, rester sur if.

# Quiz de révision

Testez vos connaissances — cliquez sur la bonne réponse.

1. En bash, un test retourne 0. Cela signifie…
En bash (et Unix en général), 0 = succès = VRAI. C'est l'inverse de la plupart des langages. La logique vient des codes de retour : 0 = la commande a réussi, autre valeur = erreur.
2. Quelle syntaxe de test est recommandée dans un script bash ?
[[ ]] est la syntaxe bash étendue recommandée. Elle est plus sûre (pas besoin de guillemets obligatoires), supporte &&, ||, les globs (*.sh) et les expressions régulières (=~). Réserver [ ] uniquement pour les scripts POSIX portables (sh).
3. Quel opérateur vérifie qu'une variable de chaîne est vide ?
-z vient de zero (longueur zéro). Vrai si la variable est vide. -n (non-zero) est l'inverse : vrai si la variable est non vide.
4. Comment comparer correctement deux entiers a=10 et b=20 pour vérifier que a est inférieur à b ?
-lt (less than) compare des valeurs numériques. < dans [[ ]] compare des chaînes par ordre lexicographique (alphabétique), pas des nombres : "9" serait "supérieur" à "10" en comparaison de chaînes.
5. Quel opérateur vérifie qu'un chemin est un dossier existant ET accessible en écriture ?
Dans [[ ]], on combine avec && (ET). Les deux conditions doivent être vraies. || (OU) serait vrai si l'une ou l'autre est vraie — ce n'est pas ce qu'on veut ici.
6. Dans un case, que représente *) ?
*) est le cas par défaut d'un case — l'équivalent du else d'un if. Il correspond à toute valeur qui n'a pas été capturée par les motifs précédents. Il doit toujours être en dernier.
7. Pourquoi est-il dangereux d'écrire [ $a = "test" ] sans guillemets autour de $a ?
Sans guillemets, si $a est vide, bash substitue la variable par rien et obtient [ = "test" ]. Bash voit alors un opérateur = sans opérande gauche : erreur de syntaxe. Avec [[ ]] ce risque est moindre, mais l'habitude des guillemets reste bonne dans tous les cas.
