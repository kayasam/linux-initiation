Dans le fichier accueil.sh

accueil.sh · fichier texte

Un script reste un fichier texte. Bash lit ses commandes dans l’ordre, ce qui permet de les relancer sans tout retaper.

Le shebang

Quel interpréteur doit lire le fichier ?

Lors d’un lancement direct avec ./accueil.sh, cette première ligne demande Bash. /usr/bin/env le recherche dans PATH.
./accueil.sh Mila
→ Bash lit les commandes du fichier.
Tout en haut. Le shebang se place sur la première ligne. Quand on lance bash accueil.sh, on a déjà choisi Bash.
Mini-atelier · nano simulé

Le fichier est saisi. Comment le garder ?

Dans Debian, tu ouvres nano accueil.sh. Une fois le texte saisi, reproduis la séquence d’enregistrement avec les boutons.

{ }
accueil.shModifié · pas encore enregistré
1 / 4 — Le texte est dans l’éditeur. Commence par Ctrl+O.

Dans nano, ^O et ^X signifient Ctrl+O et Ctrl+X. Sur Debian, nano enregistre avec les fins de ligne Linux habituelles (LF).

Pourquoi ce petit ./ ?

Supposons que le dossier courant n’est pas dans PATH. Quelle écriture permet de désigner le fichier ?

Le point désigne le dossier courant. Le / fait de ./accueil.sh un chemin : Bash ne cherche plus ce nom dans PATH.

Ton atelier sur Debian

mkdir -p ~/atelier-bash/scripts
cd ~/atelier-bash/scripts
nano accueil.sh
Ton dossier, tes fichiers. Aucun sudo n’est nécessaire pour créer et lancer ce script dans ton dossier personnel.

Une erreur qui mentionne bash\r peut venir de fins de ligne Windows (CRLF). Enregistre le script en LF.

ORION · ROBOT D’ACCUEIL
Le robot utilise prenom="${1:-visiteur}", puis echo "Bienvenue $prenom sur $station.".
Ici, les commandes commencent par bash accueil.sh : $0 vaut accueil.sh. Avec ./accueil.sh, $0 vaudrait ./accueil.sh.


Les arguments gardent leur frontière
echo "Nombre : $#"
printf 'Argument : %s\n' "$@"
"$@" transmet chaque argument séparément. printf réutilise son format pour les arguments suivants. Avec zéro argument, ce format affiche malgré tout une ligne vide.

-n lit la syntaxe sans exécuter les commandes. Une commande inconnue peut donc passer cette vérification.


$? · la dernière commande seulement
Attrape le code avant qu’il change
Les boutons sont exécutés dans l’ordre de tes clics. Provoque un échec, capture le code, puis essaie echo.
0
Valeur actuelle de $?
code n’a pas encore été affectée.
Au départ, la commande précédente a réussi : $? vaut 0.
À lire tout de suite. 0 signifie réussite selon les règles de la commande. Un autre code indique un échec ou un autre résultat, selon la commande.


bash -x · pas à pas
Regarde les valeurs se remplacer
bash -x accueil.sh "Mila Vega"
  1. + prenom='Mila Vega'Le premier argument devient la valeur de prenom.
  2. + station=OrionLa variable station reçoit Orion.
  3. + echo 'Bienvenue Mila Vega sur Orion.'La trace montre la commande après expansion.
  4. Bienvenue Mila Vega sur Orion.Cette ligne est la sortie normale de echo.
0 / 4 — Avance pour découvrir la trace du script correct.
Les lignes avec + sont la trace, envoyée sur la sortie d’erreur ; le message d’accueil est la sortie normale. Les commentaires et le shebang n’y sont pas exécutés comme des commandes.
